# 水果素材生图提示词

## 目标
为《果了个果》准备基础水果素材。每种水果输出 `3` 张图：

- `A`：完整水果或最典型形态
- `B`：处理后的水果形态 1
- `C`：处理后的水果形态 2

要求同一种水果的 3 张图一眼能看出是同类，同时形状、角度、大小略有变化，方便在碗里堆叠时形成层次感。

## 水果捞场景切块尺度（B / C 必遵守）
用于碗内捞取的小块食材，**B、C 体积要小**，符合「水果捞」逻辑，禁止「半只苹果、半颗桃、整圈厚菠萝环」等过大切面。

- **苹果**：仅 **1/8 小扇块、小 wedge 或小方丁**，红皮 + 浅黄果肉 + 果芯纹理可辨，禁止半颗苹果。
- **橙子 / 柠檬**：**薄圆片或小扇形薄片**（像饮品/捞料里的橙片、柠檬片），角度略转区分；禁止过大整瓣。
- **香蕉**：**剥皮后**的 **短小段**（约一指节～两指节长）或 **薄横片**，乳黄果肉 + 边缘略深黄；禁止连整根弯蕉皮带大段。
- **桃子 / 芒果**：**小方丁或小厚片**，保留果皮色边与果肉色对比；禁止大半截面占满格。
- **草莓 / 猕猴桃**：**小厚片、1/4 小块或小丁**，籽/黑心等识别特征保留；避免半颗唯一大切面撑满。
- **西瓜**：**小丁或小块**，红瓤黑籽，**无绿色外皮**；同形不同角。
- **菠萝**：**小丁或薄环上取下的一小段弧条**，黄肉 + 眼孔纹理；禁止整圈厚环独占一格。
- **葡萄**：**2～4 粒**小簇或单粒，明显小于整串展示。
- **蓝莓**：单颗或两颗组合即可，B/C 仍要小体量、易堆叠。

定稿资源可与旧版并存：文件名加后缀示例 `fruit_apple_a_bowl.png`（旧 `fruit_apple_a.png` 保留不删）。

## 统一画风规范
- 2D 手绘卡通食物插画风，和参考图里的食材风格一致
- 颜色鲜艳、高饱和、有食欲，边缘线稿清晰但不过度粗黑
- 俯视偏斜 3/4 视角，适合放进火锅/水果碗里堆叠
- 轮廓完整、识别度高，避免过多写实细节
- 同系列统一光照方向，统一阴影方式，统一材质表现
- 单个主体居中，透明背景
- 不要盘子、桌子、手、刀叉、文字、水印、边框、装饰背景
- 输出 PNG 素材感，适合小游戏点击物件

## 通用基础提示词
每个单独提示词都建议默认带上这段基础风格描述：

```text
微信小游戏食材素材，2D手绘卡通风，俯视偏斜3/4视角，边缘线稿清晰，颜色鲜艳饱和，有食欲，主体完整清晰，透明背景，单个物体居中，不要文字，不要水印，不要边框，不要盘子，不要背景场景，适合作为小游戏中可点击的食材图标。
```

## 通用负面要求

```text
不要写实摄影，不要复杂背景，不要多物体组合，不要 UI，不要拟人表情，不要餐具，不要桌面，不要光污染，不要模糊，不要裁切，不要低饱和，不要灰脏颜色。
```

## 推荐出图参数
- 模型：`gemini-3.1-flash-image-preview`
- 比例：`1:1`
- 尺寸：`512` 起步，定稿可升到 `1K`
- 每个提示词建议至少出 `2-4` 张，从中挑选最统一的一组

- `fruit_strawberry_b.png`
- `fruit_strawberry_c.png`
- 其他水果同理

## 批量生图建议
- 先按完整水果 `A` 版全部出一轮，确认整套风格统一
- 再按切片/切块 `B/C` 版补充
- 同一种水果最好在同一轮里连续生成，减少模型画风漂移
- 如果某个水果识别度不够，优先强化它的轮廓特征，而不是增加装饰

## 选图标准
- 缩小到小游戏尺寸后仍然一眼能认出水果种类
- 同一种水果的 `A/B/C` 版颜色、线稿、材质一致
- 不同水果之间色相差异足够明显
- 放到同一个碗里时不会混成一团
