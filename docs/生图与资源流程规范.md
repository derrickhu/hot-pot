# 生图与资源流程规范（hot-pot）

以下流程适用于本项目及与本仓库配套的美术资源工作流。**未确认前，任何资源不得直接写入游戏仓库的 `hot-pot/assets/`。** 顺序是：**先在资源目录里落抠图结果 → 你确认无误 → 再拷贝进游戏仓库**；游戏目录里只保留已确认进包的版本。

---

## 1. 先写提示词，落盘 `docs/`

- 生图前必须写好提示词（含画风约束、尺寸、版式、负向词等）。
- 文件放在本仓库 **`docs/`** 下（常用子目录 **`docs/prompt/`** 存放英文整段 prompt；也可与 `docs/水果素材生图提示词.md` 等并列）。
- 便于版本管理、复现与交接。

---

## 2. 使用 Cursor 自带的 **GenerateImage** 出图

- 在对话中通过 **GenerateImage** 生成图片（与提示词一致）。
- 生成物先进入工作区临时路径时，按第 3 步立刻归集到资源暂存目录。

---

## 3. 资源目录（本机）：所有生图与抠图结果先写这里

**根路径：**

`/Users/rosa/rosa_games/game_assets/hot-pot/assets`

- **原始生成图**、**中间步骤**（未抠图、裁切前备份等）放在此根下子目录即可，例如 `raw/`、`matte/`、`trim/`、`sheets/` 等，命名清晰。
- **抠图 + 裁透明边完成之后**，当前这一版 **立刻保存到资源目录** 下与进包命名对齐的位置，推荐：
  - **`/Users/rosa/rosa_games/game_assets/hot-pot/assets/images/`**（根级 UI / 背景 / 大图等，文件名尽量与将来 `hot-pot/assets/images/` 里一致，如 `home_play_btn.png`、`game_logo_title.png`）。
  - 水果切片等多文件：**`.../assets/images/bowl/`**（归档命名习惯即可）；确认进包后复制到游戏仓库 **`hot-pot/subpackages/bowl_game/assets/images/bowl/`**（与 `game.json` 分包 `bowl_game` 一致，主包仅保留首页等资源以控制体积）。
- **不要**在确认前进游戏仓库的 `hot-pot/assets/images/`。

---

## 4. 后处理：抠图 + 裁透明边

1. **抠图**：使用通用 **remove-background** skill（`rembg` + BiRefNet 等），按前景识别抠透明底；**不用色键**作为主流程。
2. **裁边**：去掉多余透明像素（例如本仓库 `scripts/trim_alpha_bbox.py` 按 alpha 外接矩形裁剪）。
3. 输出文件 **保存到第 3 节所述资源目录**（优先 `game_assets/.../assets/images/`）。若同一资源要试多版，可在 `trim/` 等子目录保留带 `_v2`、`_trim` 后缀的副本，**准备给你确认的那一版**用进包文件名放进 `images/`（或 `images/bowl/`）。

此阶段 **仍不** 写入 `hot-pot/assets/`。

---

## 5. 确认后，再拷贝进游戏仓库

- **只有你确认**资源目录里该文件（或该批 `bowl/` 文件）没问题、可作为进包版本后，再**复制**到游戏仓库，例如：
  - `hot-pot/assets/images/` 或与代码约定路径一致的位置。
- 拷贝时可在对话里说明版本（文件名或子目录），便于与 `docs/` 中提示词文档对应。

---

## 资源习惯：雪碧图 / 单图多帧

- **能放在一张图里的同类资源，尽量做成一张**（横排或栅格多格），生图时在提示词里写清 **总尺寸、列数/行数、每格内容**，与 `docs/prompt/bowl_tool_buttons_sheet.md` 一类文档对齐。
- 程序侧用 **`PIXI.Texture` + `PIXI.Rectangle` 裁帧** 或等价方式，从单张纹理切出多枚 UI/图标，减少文件数与加载次数。
- 若单图会过大、或资源之间画风/用途完全无关，再拆多张，并说明原因。

---

## 主包体积与压缩

- 微信小游戏**主包**含代码与未配置分包的资源，体积需控制在平台限制内；玩法用大图放在 **`subpackages/bowl_game/assets/images/`**，由 `BowlScene` 在进入关卡前 `wx.loadSubpackage` 再加载（见 `src/utils/loadBowlSubpackage.ts`）。
- 定稿图可再跑 **`npm run compress:images`**（`scripts/compress_game_images.py`，依赖本机 **Python3 + Pillow**）做无损 PNG 重打包与适度 JPEG 压缩。
- 若源图分辨率明显高于逻辑屏需求（设计宽约 **750**），可再跑 **`npm run downscale:images`**（`scripts/downscale_game_textures.py`）按约定上限缩小像素尺寸后再进包；仍偏大时可用 **pngquant** 等对带透明 UI 做有损压测。

## 与现有文档的关系

- 具体单资源的 prompt 仍写在 **`docs/prompt/`** 或相关专题 md 中。
- 本文档描述 **跨资源的流程与目录约定**；新增资源类型时，先补 **提示词文档**，再按 **资源目录（生图 → 抠图/裁边即落盘）→ 你确认 → 拷贝进游戏仓库** 执行。
